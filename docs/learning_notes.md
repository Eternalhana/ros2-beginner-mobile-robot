# 学习笔记：一只小乌龟，两个频道

## 1. 谁发指令？谁汇报结果？

**节点**就是一个承担具体任务的 ROS 程序。**Topic（话题）**是一个有名字的消息频道。发送消息的一方叫发布者，接收消息的一方叫订阅者；同一个节点可以身兼两职。

```text
键盘程序 或 square_driver ── /turtle1/cmd_vel（要求怎么动）──▶ Turtlesim
square_driver            ◀── /turtle1/pose   （实际在哪里）── Turtlesim
```

`/reset` 是另一类通信：调用一次，请对方办一件事，等它答复。这叫服务，不是不断播报的 Topic。

## 2. 四个按键的实测

键盘输入由辅助工具送入官方 `turtle_teleop_key` 的终端，不是绕过键盘直接发指令。以下数值均来自运行中的 ROS 消息，四舍五入显示。

| 输入 | 前进速度 | 转动速度 | 看到的数据变化 |
|---|---:|---:|---|
| ↑ | 2.0 | 0 | 朝右时，x 从 5.5444 到 7.5604，y 不变 |
| ← | 0 | 2.0 | x、y 不变，朝向从 0 到约 2.016 弧度 |
| → | 0 | -2.0 | x、y 不变，朝向从约 2.016 回到约 0 |
| ↓ | -2.0 | 0 | 朝右时，x 从 7.5604 回到 5.5444 |

一次方向键不是“固定转 90°”。本项目的 Python 节点能画方形，是因为它读回朝向、接近目标时减速，而不是假设一次按键就够了。

## 3. 第一次读 Python，只看三个地方

打开 [draw_square.py](../ros2_ws/src/beginner_robot/beginner_robot/draw_square.py)。

1. `command()` 是“脚和方向盘”。只给 `forward` 就直走，只给 `turn` 就原地转；都不填就是发停车指令。
2. `drive_side()` 先记起点，再用 `math.hypot()` 算当前点和这条边起点的直线距离。走到 `SIDE` 就停。它不用猜电脑跑了多少秒。
3. `draw()` 是路线。`range(1, 5)` 依次取 1、2、3、4，不包含 5。每轮走一条边，再把朝向调到 90°、180°、270°、360° 中的下一个。角度在程序里用弧度表示，π/2 等于 90°。

这是一种简单的**反馈控制**：先发命令，再看实际结果，然后决定继续还是停。小乌龟撞墙、位置消息中断等情况设有等待上限；不要在同一时间用键盘和 Python 抢着控制它。

## 5. Git 和 GitHub 是两件事

Git 是电脑里的历史记录工具；GitHub 是可以托管这份历史的网站。**本地提交不等于已经上传。** 在 Windows PowerShell 中可用 `git log -1 --oneline` 查看最近一次本地存档；先用 `cd D:\ROS2-Projects\ros2-beginner-mobile-robot` 进入项目。

以后改完一个小功能，可以分三步操作：

1. 用 `git status` 查看改了什么，然后用 `git add README.md` 选择这次要存档的文件（这里只举 README 为例）。
2. 用 `git commit -m "补充操作说明"` 在本地保存这个版本，说明写改动的真实目的。
3. 建好属于自己的空 GitHub 仓库后，用 `git remote add origin 仓库的HTTPS地址` 连接目标仓库（最后一段要替换成真实地址），再用 `git push -u origin main` 上传。第一次登录在 GitHub 官方窗口完成，不把密码或令牌写入 README 或聊天。后续通常只需 `git push`。

首次创建远程仓库时不要再勾选生成 README、.gitignore 或许可证，以免跟本地已有历史冲突。公开仓库之前，检查 Git 提交署名、邮箱、截图等是否适合公开。没有为本项目预先选择开源许可证。
